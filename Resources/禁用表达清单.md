# 禁用表达清单

这个文件用于沉淀写作中的“坏味道”。

它不是为了把语言变得统一，而是为了避免文章滑向：

- AI 腔；
- 公众号模板腔；
- 咨询报告腔；
- 过度宏大叙事；
- 正确但没有体感的废话。

原则：**能具体就不要抽象，能说人话就不要端着，能用场景说明就不要空喊判断。**

---

## 1. 绝对禁用词

| 禁用表达 | 为什么不好 | 替代方式 |
|---|---|---|
| 总而言之 | AI / 作文收尾感强 | 直接写结论 |
| 综上所述 | 太像报告，不像文章 | 删除或换成自然转折 |
| 毋庸置疑 | 没有说服力，只是在装确定 | 给证据或删掉 |
| 不言而喻 | 如果真不言而喻，就不必写 | 删掉 |
| 显而易见 | 容易显得傲慢 | 写出为什么明显 |
| 值得注意的是 | 空泛提示语 | 直接进入重点 |
| 从某种意义上说 | 犹豫但不提供边界 | 要么直说，要么说明条件 |
| 可以说是 / 可谓是 | 没有信息增量 | 删除 |
| 在当今社会 | 宏大废话 | 直接进入具体场景 |
| 随着科技发展 | 模板化开头 | 写具体技术 / 事件 |
| 打破传统 | 空泛 | 写到底打破了什么机制 |
| 重新定义 | 滥用 | 写具体改变了什么关系 |
| 赋能 | 大厂黑话 | 写“让谁能做什么” |
| 闭环 | 如果没有反馈机制就是滥用 | 写清楚输入、动作、反馈 |

## 2. 高风险句式

### 2.1 机械并列

不要写：

```text
一方面……另一方面……
不仅……而且……
首先……其次……最后……
```

替代：

- 用“但”“问题是”“更麻烦的是”；
- 用具体场景自然推进；
- 如果必须列举，确保每一项都有信息增量。

---

### 2.2 假深刻句式

不要写：

```text
这不仅是 X，更是 Y。
这背后折射出的是……
这无疑给我们带来了深刻启示。
```

替代：

- 直接写 Y；
- 写具体机制；
- 用一个场景让读者自己感受到“背后”。

---

### 2.3 人生导师腔

不要写：

```text
我们都应该……
让我们一起……
真正成熟的人……
人生最重要的是……
```

替代：

- “我踩过的坑告诉我……”
- “更现实的问题是……”
- “如果只改一件事，我会先改……”

---

### 2.4 空泛共情

不要写：

```text
每个人都会有这样的时刻。
这或许就是生活。
愿你我都能……
```

替代：

- 写一个具体时刻；
- 写一个真实动作；
- 写一个读者能识别的细节。

## 3. 英文括注规则

Garron 可以中英混用，但不要滥加英文括注。

### 可以保留英文

- 缩写或专有协议：MCP、A2A、API、Agent；
- 原文概念不可替代：Jobs to be Done；
- 读者需要英文才能继续搜索资料。

### 应该删除英文

- 情绪词英文翻译；
- 已经有清晰中文表达的概念；
- 为了显得专业而加的括注。

不要写：

```text
情感麻木（emotional numbing）
认知失调（cognitive dissonance）
```

除非这篇文章真的需要读者进一步检索该英文概念。

## 4. 标点坏味道

### 4.1 破折号滥用

不要用破折号制造虚假节奏。

```text
这不是效率问题——而是权力问题。
```

可以改成：

```text
这不是效率问题。它更像是权力问题。
```

### 4.2 引号滥用

不要给普通词加引号来显得有洞察。

```text
真正的“成长”不是……
```

如果不是引用、反讽或特定概念，删掉引号。

### 4.3 感叹号滥用

全文最多 1-2 个。大多数时候，判断本身应该有力度，不靠感叹号撑。

## 5. 抽象词替换表

| 抽象词 | 更好的追问 |
|---|---|
| 价值 | 对谁有用？怎么有用？ |
| 影响 | 影响谁？影响什么决策？ |
| 赋能 | 让谁以前不能做、现在能做什么？ |
| 生态 | 里面有哪些角色？谁依赖谁？ |
| 系统 | 输入、动作、反馈分别是什么？ |
| 机制 | 谁被奖励？谁承担代价？ |
| 体验 | 哪个具体环节让人舒服 / 痛苦？ |
| 焦虑 | 身体和行为上具体表现为什么？ |
| 高级感 | 哪些元素更克制、更可信、更少噪音？ |

---

## 6. 保留 Garron 个人表达

不要误删这些个人特征：

- 顿号密集列举；
- 括号里的轻微自嘲；
- 中英混用；
- 管理学 / 社会学 / 技术概念的横向连接；
- 现实的理想主义者式收束；
- 对“结构性问题”和“个体体感”的并置。

关键区别：

```text
个人风格 = 有具体经验支撑的表达习惯
AI味 = 没有具体经验支撑的漂亮句式
```

## 7. 新增禁用项规则

每次 Writing Review 发现新的坏味道，就追加到这里。

格式：

```markdown
## 新增：表达名称

- 为什么不好：
- 替代写法：
- 来源文章：
```
